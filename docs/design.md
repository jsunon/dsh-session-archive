# 设计说明

这份文档讲 dsh-session-archive 是怎么判定的、为什么这么判。安装与使用见 [README](../README.md)，配置项见 [config.md](config.md)。

## 会话类型判定：维度，不是单选

会话不是「开发/提问/修复」三选一，而是若干产出维度的叠加，类型只是维度的投影。

| 维度 | 含义 | 激活的桶 |
| --- | --- | --- |
| `DEV` | 造新东西（插件/组件/库） | 01-成品、02-源码、03-工具 |
| `FIX` | 修已有东西 | 02-源码 |
| `ASK` | 只问不改 | 05-参考 |
| `OPS` | 部署/运维/服务器 | 03-工具、04-产物 |
| `DOC` | 文案/报告/方案 | 04-产物、05-参考 |
| `DATA` | 统计/清洗/导出 | 04-产物、03-工具 |

**信号三级加权**——措辞会骗人，磁盘不会：

| 级别 | 内容 | 权重 |
| --- | --- | --- |
| `L1` 结构 | 清单文件、同模块 ≥3 块、路径互引、同文件反复改写、补丁块、远程命令、产出扩展名、零写盘零执行 | ×3 |
| `L2` 语义 | 关键词命中（报错/部署/文案/统计…） | ×2（命中次数封顶 3 次，单维上限 45） |
| `L3` 上下文 | 会话标题 | ×1 |

阈值：`high ≥ 70`、`medium 40–69`、`low < 40`。低于 `medium` 的维度不激活，不建桶。

并列时按固定顺序破平：`DEV > FIX > OPS > DATA > DOC > ASK`（只保证结果确定，不制造偏好）。


## 文件路由：七级优先级

越靠前越重要，越靠后越可疑。误判成「可删」翻一下找回来；误判成「成品」可能把 token 传上 GitHub——所以**可疑的往可删那边倒**。

| 优先级 | 判定 | 去向 |
| --- | --- | --- |
| 1 | sha256 与已有文件相同 | `_临时/重复/` |
| 2 | 属于交付单元（含清单文件 / 同模块成组） | `01-成品/<包名>/` |
| 3 | 源码角色（原始 / 补丁 / 快照） | `02-源码/<角色>/` |
| 4 | 含函数/类定义，或 `.yml/.yaml/.toml/.ini/.conf/.env/.xml/.json` 且 ≥3 行 | `03-工具/` |
| 5 | 非代码产出（图片/表格/文档） | `04-产物/{长期,一次性}/` |
| 6 | 外部资料 / 咨询会话里的示例代码 | `05-参考/` |
| 7 | 无匹配规则 | `_临时/未归类/` |

额外规则：文件名带 `tmp-/test-/临时/草稿` 前缀，或 ≤15 行的一次性探测命令（`curl`/`nc`/`ping`…），直接进 `_临时/探测/`。

第 4 级**不看维度**（只有「纯咨询会话」这一个例外）：排错会话里贴出来的脚本、改过的 `nginx.conf` 一样能拿去复用，不该因为 FIX 维度只规划了 `02-源码` 就被当成垃圾。维度只决定**候选桶**，路由决定**每个文件的实际归属**；两者冲突时按需实体化桶——文件先落到 `03-工具/`，桶随之出现。


## 语义命名：不再有 `代码-104-1-2.json`

代码块的文件名按四优先取名：

1. 首行注释；注释里若写了文件名（`# C:\…\cordis.patch.yml 追加`、`// lib/store.js`、`# /etc/nginx/nginx.conf`），直接取路径末段的真名 → `cordis.patch.yml` / `store.js` / `nginx.conf`。**不会**把整条路径压成 `C-Users-example-dsh.yml` 这种鬼名字。
2. 首个函数/类/导出名（`export function buildName()` → `buildName.js`）
3. 内容自证身份：`{"name": …, "version": …}` → `package.json`；`- id:` + `disabled:` → `cordis.patch.yml`
4. 代码块前一段正文，但**只接受干净的短标签**（`重启前先记录当前状态`、`看告警历史`）；正文是散文时（`Funnel 之后：`、`**4. relay concurrency gate（2 处）**`、`每天早 9 点，把磁盘和内存情况发到 Telegram`）宁可不要
5. 兜底 `片段-<条号>-<块号>.后缀`

> **为什么宁可用兜底名**：`片段-074-01.sh` 是诚实的——它说「我不知道这是什么」。而 `每天早-9-点-把磁盘和内存情况发到.sh` 是撒谎的——它让人以为那是个有意义的标识。命名失败可以补救，误导不行。

同名不同内容用 **`.vN`** 版本号（`buildName.v2.js`），**永不用 `-2`**——那是重复的标志，不是版本。

文件名统一过 `tidyStem()`：全角标点（`，、；：（）【】「」《》·—…`）与空格折叠成 `-`，连续 `-` 折叠，超长时拉丁词回退到词边界，避免切出 `MySQL-的-innodb buffer po.sql` 这种半截名。

> **历史会话的诚实兜底**：旧版归档时代码块一抽走，正文里只剩 `> 代码已单独保存…` 占位，前文已不可逆丢失。迁移这类会话时，`bin/chat-blocks.mjs` 会尽力从 `聊天记录.md` 的围栏里捞回前文；捞不到的仍叫 `片段-NNN-NN`——这是对「不知道就叫不知道」的忠实，不是命名失败。


## 内容去重：从写盘那一刻根治

旧版每写一个代码块就判「路径存在」→ 加 `-2`，从不比内容。同一段代码写两遍就多一个副本，一次会话能攒出 72 个。

现在：写盘前先算 `sha256`（归一化换行与行尾空白），命中已有内容 → 进 `_临时/重复/`，不写第二份。同时用**幂等键** `sha256(sessionId|seq|blockNo|contentHash)` 记在 `_临时/.archive-state.json`，重跑归档不会重复写。


## 开源前安全扫描

落盘后扫全树，只跳过 `02-源码/原始/`（上游原件）、`_临时/重复/`（字节级副本）、`node_modules/`、`.git/`——`_临时/未归类/` 与 `_临时/探测/` **照扫**，那两处恰恰最容易藏硬编码密钥。命中即分类：

| 级别 | 规则 | 效果 |
| --- | --- | --- |
| `block` | OpenAI key、GitHub token、AWS AccessKey、Slack token、私钥文件内容 | `01-成品` 不可发布，README 标红 |
| `warn` | 硬编码口令、Windows 绝对路径、POSIX 家目录、内网 IP、本机 DSH 目录 | 可发布，但需人工确认 |
| `info` | `127.0.0.1` / `localhost` | 仅记录 |

命中样例打码保存（保留前 4 后 4），避免扫描报告本身泄露密钥。


## 审计链

每个文件一条 `reason`，写进 `MANIFEST.json`：

```json
{
  "path": "01-成品/dsh-demo-plugin/lib/index.js",
  "bucket": "deliver",
  "confidence": "high",
  "sha256": "…",
  "source": { "msgRef": "seq-2", "blockNo": 2 },
  "reason": "属于交付单元（含清单文件或同模块成组）",
  "deletable": false,
  "readonly": false
}
```

`README.md` 是人读版：会话类型判定表（含依据）、产物清单（哪些可删）、待人工确认项、可直接删除清单、开源检查结论。

判定错了不用改代码：`POST /dsh-session-archive/api/override` 锁死维度，之后插件不再自动改判。


## 触发规则

| 触发 | 行为 |
| --- | --- |
| 新建会话（`session/created`） | 等待 `settleMs` 后建目录、判定维度、建桶、写清单 |
| 会话产出消息（`user/message`、`turn/end`） | 追加聊天记录；新代码块按语义命名落桶 |
| 标题生成/更新（`session/title`） | 重新排程，必要时整体改名 |
| 会话结束（`session/disposed`） | 收尾，取消定时器 |
| 兜底扫描（每 `tickMs`） | 补写增量、处理标题晚到、迁移旧碎片、清理历史文件 |


## 只读四重保险

`02-源码/原始/` 承诺「永不修改」，靠四层保证：

1. 目录里放 `.READONLY` 标记文件
2. `MANIFEST.json` 里该目录下每个文件 `readonly: true`
3. 写盘时硬跳过 `readonly` 目标（不靠约定，靠代码）
4. `README.md` 明写「修改请到 02-源码/补丁/ 或 02-源码/快照/」

## 测试

```bash
node tests/naming.test.mjs        # 命名规则（12 项）
node tests/classify.test.mjs      # 分类流水线纯函数（50 项）
node tests/pipeline.test.mjs      # 端到端落盘（12 项）
node tests/plugin.test.mjs        # 插件接口 + 幂等（7 项）
node tests/chat-blocks.test.mjs   # 聊天记录前文复原（6 项）
node tests/routes.test.mjs        # HTTP 路由注册 + import 完整性（6 项）
```

`pipeline.test.mjs` 在临时目录真跑落盘，覆盖：维度识别、建桶、清单生成、语义命名、去重、幂等、旧碎片迁移、安全扫描阻断、覆盖锁。

`routes.test.mjs` 用假的 `ctx.inject(['webServer'])` 抓注册调用，断言 10 条 HTTP 路由齐全，并做一次静态检查：`lib/index.js` 里用到的 `./layout.js` 导出必须在 import 列表里（曾经 `planLayout` 漏 import，路由注册成功但每次调用都报 `planLayout is not defined`）。**不重启宿主也能确认新代码会不会被注册**，这是排查「`/api/health` 返回 200 但代码是旧的」的最快手段。
